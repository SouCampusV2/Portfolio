# Синхронизация портфолио с проектами

Цель: всё, что сайт говорит о проектах, — **свежее и правда**. Портфолио не
читает чужой код; у каждого проекта есть паспорт `PORTFOLIO.md`, который
обновляет сессия этого проекта (шаг в её `wrap-day`). Здесь — как перенести
паспорта на сайт.

Запуск: команда `/sync-portfolio` (`.claude/skills/sync-portfolio/SKILL.md`)
или фраза «синхронизируй портфолио». Раз в 2–4 недели и после заметного шага в
любом проекте (запуск, новая цифра, новый проект).

## Источники

| Проект | Паспорт | Локально | На GitHub (если локальной копии нет) |
|---|---|---|---|
| SouCampus builds (сайт) | `PORTFOLIO.md` | `Claude/FirstTry` | `SouCampusV2/soucampusWeb`, ветка `dev` |
| BotCampus (Discord-бот) | `PORTFOLIO.md` | `Claude/botds` | `SouCampusV2/soucampusBot`, ветка `dev` |
| SouTools (Axiom) | паспорта нет — `README.md` | `Claude/soucampusAxiomTools` | `SouCampusV2/soucampusAxiomTools` |
| Java: API переводов | паспорта нет | `Claude/bank-transfer-api` | — (нет удалённого репозитория на 14.11) |

Новый проект — завести ему паспорт по образцу `Claude/botds/PORTFOLIO.md` и шаг
5a в его `wrap-day`, потом добавить строку сюда.

Читать с GitHub: `gh api repos/<repo>/contents/PORTFOLIO.md?ref=dev --jq .content | base64 -d`.

## Порядок

1. **Прочитать** `REDESIGN_BRIEF.md` (разделы 2–3 — правила и факты) и каждый
   паспорт. Взять из паспорта журнал изменений с даты прошлой синхронизации
   (последний файл в `docs/sync/`).
2. **Сверить** с сайтом: `content/site.ts` (карточки, опыт, стек, цифры,
   `cases`) и схемы `components/diagrams/`. Для каждого расхождения решить, к
   какому классу оно относится:
   - **А. Без вопросов** — статус, формулировка, новая функция без цифры,
     закрытая или новая цель в «What is next». Применить.
   - **Б. Нужен владелец** — новая или изменённая цифра, новый клиент или
     компания, новое утверждение о роли, всё, что на интервью спросят
     «расскажи подробнее». **Не применять**, вынести в отчёт с вопросом.
     После «да» — применить и записать факт в раздел 3 брифа.
   - **В. Перерисовать** — в журнале паспорта отмечено, что поменялся путь
     заказа, статусы, модули или схема работы. Поправить компонент схемы.
3. **Проверить живое**, без доверия памяти:
   - ссылки проектов отвечают (`curl -s -o /dev/null -w "%{http_code}"`);
   - сайты проектов открываются и выглядят как на скриншотах; если сильно
     изменились — пометить «переснять видео/скриншоты» (инструкция в памяти
     Claude: `recording-project-media`);
   - числа, которые даёт команда (тесты, коммиты), — пересчитать командой.
4. **Правила брифа** перед сохранением: ничего из правила 3 (AI-инструменты,
   Token HUD, Mojang/Microsoft), детали аудитов не выносить, роль в BotCampus и
   SouTools — «I built», без «wrote every line», английский B1–B2.
5. **Собрать**: `npm run build`; текст страницы без дублей (извлечение текста,
   как в шаге 1 редизайна).
6. **Закоммитить** по одному коммиту на смысловую правку, запушить `redesign` и
   `main` (владелец разрешил пушить в `main` без отдельного «ок»).
7. **Отчёт**: файл `docs/sync/ГГГГ-ММ-ДД.md` и короткое сообщение владельцу:
   - что обновлено на сайте (класс А и В);
   - **что ждёт ответа** (класс Б) — списком вопросов;
   - чьи паспорта не обновлялись дольше месяца — напомнить;
   - что переснять.

## Чего не делать

- Не править чужие репозитории ради портфолио: не тот паспорт — сказать
  владельцу или обновить паспорт в сессии того проекта.
- Не придумывать цифры «по коду» без даты и источника.
- Не переносить в портфолио цели, которые владелец не готов показывать (в
  паспорте — только то, что можно показать).
